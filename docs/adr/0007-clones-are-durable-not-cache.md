# ADR-0007: A clone is durable data, not cache

- Status: accepted
- Date: 2026-09-16

## Context

Adding a repo needed a path on this machine. A git URL names one that does not
exist yet, so cloning has to put it somewhere, and there were three candidates:
a temp directory, a subdirectory of `cache_root`, and a root of its own.

The cache already has a deletion path pointed at it. `reposhape forget` and
`DELETE /api/repos/{key}` remove artifacts under `cache_root`, and the whole
directory is safe to delete by hand at any time, because every byte in it is
regenerated by re-running an analysis in seconds.

That is not true of a clone. A clone is the repository: re-obtaining it costs a
download, needs the network, needs credentials for a private repo, and for a
repo that has since been deleted upstream it is not possible at all. The
analysis is the cheap half.

## Decision

Clones live under their own root, `settings.clone_root`, defaulting to
`$XDG_DATA_HOME/reposhape/clones` or `~/.local/share/reposhape/clones`,
and never under `cache_root`.

Layout is `<host>/<owner>/<name>`, as `ghq` and `go get` do it, so the directory
is browsable and two repositories called `foo` from two hosts are two
directories.

Nothing in this tool deletes a checkout. `forget` removes cache artifacts and
says so; the clone it was analysed from stays.

## Consequences

- "Clear the cache" and `reposhape forget` cannot cost a download. That separation is
  the point of the ADR and it is enforced by the roots being different, not by
  remembering.
- A clone outlives everything else here, including this tool. Disk fills with
  checkouts nobody prunes, and pruning is a manual `rm` on a path the UI and
  `reposhape clone` both print. Automating it would be the one operation that can
  destroy something expensive, so it is deliberately absent rather than
  deferred.
- Because the checkout is ours, refreshing one may fetch it, which is not true
  of any other repo here. That is the one place this tool writes to a working
  tree, and it is gated on the clone root, on HEAD being on a branch, and on no
  tracked file being modified. Untracked files stay, which keeps
  `.reposhapeignore` safe. Recorded here rather than left to the code, because
  "nothing deletes a checkout" above is what makes a `reset --hard` acceptable
  at all: the boundary is ownership, and both halves depend on it.
- The cloned path is an ordinary directory to the rest of the tool: the cache
  key is derived from it like any other path, it appears in the picker as a
  folder, and re-analysing it reads the working tree. No clone-aware branch
  exists anywhere downstream.
- Clones are shallow (`--depth 1 --single-branch`), because the analysis reads
  the working tree and never the history. When co-change coupling from git
  history (deferred in `AGENTS.md`) arrives, it will want `git fetch
  --unshallow` rather than a different clone location, so this decision does
  not block it.
